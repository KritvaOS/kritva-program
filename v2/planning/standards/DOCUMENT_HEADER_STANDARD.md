# Kritva Document Header Standard

| Property | Value |
|---|---|
| Document ID | KOS-STD-DOCHDR |
| Repository | `KritvaOS/kritva-program` |
| Document Type | Standard |
| Status | PROPOSED (pilot in kritva-program, D-055, revised by audit round 1, D-056) |
| Owner | Dinesh (program owner) |
| Authority | AUTHORITATIVE for the header of detailed Markdown documents |
| Related | [README_STANDARD.md](README_STANDARD.md) |

## 1. Scope

The README standard covers a repository's root `README.md`. This standard covers the header of a detailed, **human-maintained** Markdown document that a README links to: an architecture document, specification, plan, procedure or report. It is a default for those documents, not a universal wrapper.

- A **generated** file keeps its generator marker and gets no second status or authority line. Its provenance is the marker.
- A **structured or controlled record** (the decision log, an approval ledger, a gate register, a JSON input) keeps the schema and fields it already has. Do not add a status or authority declaration that could contradict the record's own governance.
- Apply this header only where it is compatible with the owning document's rules.

Existing documents are not rewritten in one sweep. A document gets this header when it is next edited for another reason.

## 2. Header

```markdown
# <Document title>

| Property | Value |
|---|---|
| Document ID | <stable ID or N/A> |
| Repository | `KritvaOS/<name>` |
| Document Type | <Architecture / Specification / Plan / Procedure / Report / Standard> |
| Status | <DRAFT / PROPOSED / APPROVED / DEPRECATED> |
| Owner | <person or team> |
| Reviewer / Approver | <role, name or N/A> |
| Version | <document version> |
| Last Updated | <YYYY-MM-DD> |
| Authority | <AUTHORITATIVE / INPUT / GENERATED / SNAPSHOT / EVIDENCE / REFERENCE> |
| Related Tasks / Milestones | <IDs or N/A> |
| Related Documents | <links or N/A> |

## Purpose

<What the document is for and who reads it.>
```

## 3. Rules

- **Status is earned.** A document is not `APPROVED` without the approval its repository requires, recorded where that repository records approvals. A document that needs no formal approval uses `DRAFT` or `PROPOSED` and never invents an approval.
- **Version is not the release version.** The document version and the repository release version are separate.
- **Dates are ISO** (`YYYY-MM-DD`).
- **Generated documents** name the tool and the inputs, and say not to edit by hand. The existing marker is `<!-- GENERATED by <tool> from <inputs>. Do not edit by hand. -->`.
- **Owners by role.** Where ownership is kept elsewhere (for example CODEOWNERS), the header may name the role instead of repeating a person.
- **Snapshots** name the source repository and the commit they were taken from.

## 4. Source files and scripts

This standard adds no second source-header block. Each repository keeps the header its own lint enforces. Examples at the time of writing: kritva-core, kritvaos-community and kritva-raas check an SPDX-led block with `scripts/lint/check_source_headers.py --mode tracked --strict`. The license line in a header is the repository's real license; it is never copied from another repository.

Not required: Git history or timestamps in every file, comments in formats that cannot hold them, or boilerplate in generated files, vendored code and lockfiles.
